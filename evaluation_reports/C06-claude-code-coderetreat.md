## Run-specific recommendations

- **Check which JDK the build tool is actually using, not which JDK the shell's bare `java -version` reports.** Gradle resolves its daemon from `JAVA_HOME` first; this session's `JAVA_HOME` silently pointed at JDK 17 while `PATH` pointed at JDK 21, and the mismatch went unnoticed for the entire upgrade. One `./gradlew --version` at the start of validation would have caught it immediately.
- **Apply a stated version target to every file the brief's scope covers, not only to the files already carrying a malformed value.** "`sourceCompatibility` → 17" read most naturally as a flat target for the whole repository; adding it only where a bad value already existed left 17 of 22 build scripts with an unpinned, environment-dependent compile target — exactly the ambiguity the Codex pipeline run on the same target resolved more completely by adding the line everywhere.
