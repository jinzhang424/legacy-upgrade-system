The pattern across the four pairs: the full pipeline reached FBSR 1 on one of four (R13, monarch-legacy), where the matched raw run never does; on coderetreat and PeelAndSlice.Java, raw and pipeline land on the identical FBSR 0 verdict for the identical reason (pre-existing placeholder assertions, or an unexercised cross-platform leg), at 5.2× and 11.8× the raw run's cost respectively — the one exception is tv-radio, where the pipeline run (R15, initial output) was cheaper than its raw counterpart (US$16.77 vs US$21.13). [C03-claude-code-conifer.md](C03-claude-code-conifer.md) scores the third comparison run: the full-stack Conifer task of R11 given to the same general coding agent (Claude Code, Sonnet 5, high effort, 26–27 Sep). C 1, T 0, FBSR 0, BPR 0.48 (0.71 if the brief's console-clean clause is dropped), MBR 0.52, EBER 0, NBR 0.06, 257.4 M tokens, US$62.28 over 332 minutes against R11's US$41.36 over 784. All 13 services run with zero restarts, all four baseline defects are repaired, `universal-webpack` is removed outright rather than hand-patched, and — unlike R11 — the anonymous-access check survives and the collection page renders. But webpack 5's dropped `process` shim was never replaced, so the client bundle throws on every page and React never hydrates: Swagger UI renders nothing, client-side routing is gone, and the login form falls back to a native GET that puts credentials in the URL. Three further routes return SSR 500s, and R11's two redis-py regressions (bookmark lists, WARC indexing) recur — here from an explicit `redis>=5.0` pin added after auditing only the application's own redis calls, while the failing `zadd` is in pywb's. The run verified its pages with `curl`, which is the false positive the task brief warned about. It ran in an equivalent clone at the same base commit after the user said "only look at the files in this repo", so GitNexus was absent. Also an ablation point, also excluded from the aggregates above.

[D02-codex-direct-codemirror5.md](D02-codex-direct-codemirror5.md) scores the fourth comparison run and the first in the D series (Codex direct agent, no `$upgrade` orchestrator): the codemirror5 toolchain task of R10 and C02 given to Codex CLI on `gpt-5.6-sol` at medium effort, 29 Sep, in the same clone and at the same commit as C02. Where C02 refused the workspace the brief named, this run obeyed it and worked in `projects/codemirror5` for 78 minutes before the user redirected it, so GitNexus was again absent by accident. Also an ablation point, also excluded from the aggregates above.

Column notes: C is install-and-boot verified on 18 Sep 2026 by checking out each commit (R11: both the original and the upgraded Docker stacks run end to end on 24 Sep); T (declared) uses the checks the user asked for in that run, T (extended) adds the faults the user found straight afterwards (R11: faults found by the independent oracle run on 24 Sep); BPR is the share of observed reference behaviours preserved (13 tv-radio behaviours; 4 defined for CodeMirror, of which R10 observed 2; 31 for Conifer; 16–17 for coderetreat and monarch-legacy; 5 for PeelAndSlice.Java); cost is all Codex threads at GPT-5.5 list prices (R1–R9) or `gpt-5.6-sol` list prices (R10–R15, D1–D6), whichever model the run actually used; wall time is the main Codex thread including approval waits (R11 includes about three hours locked out by the account usage limit; R15's figure is summed active minutes, not wall-clock — see its table note above).

Each report has the same sections: identification, 1.1 build effectiveness, 1.2 generated tests, 1.3 behaviour preservation, 1.4 cost and efficiency, 1.5 LLM configuration, stage outcomes, what was broken afterwards ("what this run shows" in R10, R11 and D02), run-specific recommendations. The comparison reports add 1.6 position in the ablation. Evidence sources and verification methods are described in the overview's appendix.

Token accounting: for R1–R11, R12–R15 and D1–D6 tokens come from the Codex rollout logs in `~/.codex/sessions`, summed over the orchestrator and every sub-agent thread (D2 and D3 are single-threaded, so D2's sum is over its two sessions and D3's over its one; D3 uses the log's cumulative counter, with the 1.2% higher per-request sum noted in its report). For C1–C6 they come from the `cost-state` records in the Claude Code session logs under `~/.claude/projects/<slug>/`, which cover the main thread and all sub-agents, and are also recorded at the foot of each chat in `claude_refactored_chats/` (where one exists — C4–C6 have none; those reports were produced inside the live upgrade session itself). **The two families' token counts are not commensurable** — the harnesses count cached input on very different scales — so cross-family comparisons should use uncached input, output tokens, cost or wall time. D1–D6 and R12–R15 are on the same basis as R1–R11 and do compare directly with them. See the overview's "Comparison runs (C1 to C3, D2 to D3)" section.
