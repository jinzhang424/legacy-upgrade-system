[C01-claude-code-tv-radio.md](C01-claude-code-tv-radio.md) scores a comparison run on the same metrics: the tv-radio-plus-Solr task given to a general coding agent (Claude Code, Sonnet 5, 24 and 26 Sep) with no orchestrator, no generated tests, no validation gate and no GitNexus. C 1, T 0, FBSR 0, BPR 0.62, 50 of 51 dependency entries addressed, 198.9 M tokens, US$49.46 over 123 minutes. It is an ablation point, not a pipeline run, and is deliberately excluded from the aggregates above.

[C02-claude-code-codemirror5.md](C02-claude-code-codemirror5.md) scores the second comparison run: the codemirror5 toolchain task of R10 given to the same general coding agent (Claude Code, Sonnet 5, 26 Sep). C 1, T 0, FBSR 0, BPR 1.00 with EBER 1.00, 4 of 4 dependencies bumped, 4.7 M tokens, US$1.54 over 32 minutes against R10's US$7.52 over 45. Its `npm test` residual is the same six browser-driven assertions the unmodified original fails (B00), and the run isolated that itself. It refused the designated `projects/codemirror5` workspace as a suspected injection lure and worked in an equivalent clone, so GitNexus was absent by accident rather than by design. Also an ablation point, also excluded from the aggregates above.

[C03-claude-code-conifer.md](C03-claude-code-conifer.md) scores the third comparison run: the full-stack Conifer task of R11 given to the same general coding agent (Claude Code, Sonnet 5, high effort, 26–27 Sep). C 1, T 0, FBSR 0, BPR 0.48 (0.71 if the brief's console-clean clause is dropped), MBR 0.52, EBER 0, NBR 0.06, 257.4 M tokens, US$62.28 over 332 minutes against R11's US$52.71 over 784. All 13 services run with zero restarts, all four baseline defects are repaired, `universal-webpack` is removed outright rather than hand-patched, and — unlike R11 — the anonymous-access check survives and the collection page renders. But webpack 5's dropped `process` shim was never replaced, so the client bundle throws on every page and React never hydrates: Swagger UI renders nothing, client-side routing is gone, and the login form falls back to a native GET that puts credentials in the URL. Three further routes return SSR 500s, and R11's two redis-py regressions (bookmark lists, WARC indexing) recur — here from an explicit `redis>=5.0` pin added after auditing only the application's own redis calls, while the failing `zadd` is in pywb's. The run verified its pages with `curl`, which is the false positive the task brief warned about. It ran in an equivalent clone at the same base commit after the user said "only look at the files in this repo", so GitNexus was absent. Also an ablation point, also excluded from the aggregates above.

[D01-codex-direct-codemirror5.md](D01-codex-direct-codemirror5.md) scores the fourth comparison run and the first in the D series (Codex direct agent, no `$upgrade` orchestrator): the codemirror5 toolchain task of R10 and C02 given to Codex CLI 0.158.0 on `gpt-5.6-sol` at medium effort, 29 Sep, in the same clone and at the same commit as C02. C 1, T 1 against the oracle as the run left it and **0** against the oracle held fixed at the base commit, FBSR 1 / 0, BPR 1.00 with EBER 1.00 on the shared three behaviours (0.60 folding in two harness regressions), 4 of 4 dependencies pinned exactly, 952 K tokens, US$1.06 over 12.8 minutes for the evaluated session — US$5.80 over 108 minutes once the discarded predecessor session on the same brief is included. It is the first run in the corpus whose `npm test` exits 0, and the first to get there by editing the suite: three of R10's five failures were genuinely repaired (they hold in a manual browser too) and two `core_move_bidi` cases were gated off under `window.automatedTests`, removing 4 registrations (1,483 → 1,479). `test/run.js` also stopped failing on 404s, so a missing tracked asset now passes the suite silently. Its generated smoke test scores accuracy 0.40, precision 1.00, recall 0.25, F1 0.40 against a four-mutant study, detecting a strict subset of what the repository's own suite detects. Where C02 refused the workspace the brief named, this run obeyed it and worked in `projects/codemirror5` for 78 minutes before the user redirected it, so GitNexus was again absent by accident. Also an ablation point, also excluded from the aggregates above.

[D02-codex-direct-conifer.md](D02-codex-direct-conifer.md) scores the fifth comparison run: the full-stack Conifer task of R11 and C03 given to a Codex direct agent (`gpt-5.6-sol`, medium effort, CLI 0.159.2, 30 Sep – 2 Oct). C 1, T 1 declared / 0 independent, FBSR 1 / 0, BPR 0.84 (26 of 31; 0.90 if the console-clean clause is dropped), MBR 0.16, EBER 0, NBR 0, 76.7 M tokens, US$49.99 notional over about 197 active minutes (46.8 h elapsed including a usage-limit lockout). All 13 services run with zero restarts, the client hydrates, every declared page is clean in a real browser, all four baseline defects are repaired and the anonymous-access check survives. Losses are bookmark lists and WARC indexing (the redis-py regressions R11 and C03 also shipped, from a documented `--no-deps` install of pywb), React hydration errors on two logged-in pages, and an SSR 500 on the settings page. The repaired legacy pytest suite is green (521 of 522) while those regressions exist, so it cannot serve as an oracle. The 31-behaviour oracle was rebuilt, committed as `oracles/conifer-oracle.mjs`, and validated at 31/31 on a fresh build of `c406b480`. Also an ablation point, excluded from the aggregates above.

[B00-pre-upgrade-baselines.md](B00-pre-upgrade-baselines.md) scores the original, pre-upgrade commit of each project (tv-radio `c094824`, codemirror5 `6e708583`, Conifer `c406b480`) on the same metrics: CSR 0.33 as shipped, 0.67 with minimal environment fixes, and a list of corrections it implies for the run reports (not yet applied).

Column notes: C is install-and-boot verified on 18 Sep 2026 by checking out each commit (R11: both the original and the upgraded Docker stacks run end to end on 24 Sep); T (declared) uses the checks the user asked for in that run, T (extended) adds the faults the user found straight afterwards (R11: faults found by the independent oracle run on 24 Sep); BPR is the share of observed reference behaviours preserved (13 tv-radio behaviours; 4 defined for CodeMirror, of which R10 observed 2; 31 for Conifer); cost is all Codex threads at GPT-5.5 list prices; wall time is the main Codex thread including approval waits (R11 includes about three hours locked out by the account usage limit).

Each report has the same sections: identification, 1.1 build effectiveness, 1.2 generated tests, 1.3 behaviour preservation, 1.4 cost and efficiency, 1.5 LLM configuration, stage outcomes, what was broken afterwards ("what this run shows" in R10, R11 and D01), run-specific recommendations. The comparison reports add 1.6 position in the ablation. Evidence sources and verification methods are described in the overview's appendix.

Token accounting: for R1–R11 and D1–D2 tokens come from the Codex rollout logs in `~/.codex/sessions`, summed over the orchestrator and every sub-agent thread (D1 and D2 are single-threaded, so D1's sum is over its two sessions and D2's over its one; D2 uses the log's cumulative counter, with the 1.2% higher per-request sum noted in its report). For C1–C3 they come from the `cost-state` records in the Claude Code session logs under `~/.claude/projects/<slug>/`, which cover the main thread and all sub-agents, and are also recorded at the foot of each chat in `claude_refactored_chats/`. **The two families' token counts are not commensurable** — the harnesses count cached input on very different scales — so cross-family comparisons should use uncached input, output tokens, cost or wall time. D1 and D2 are on the same basis as R1–R11 and do compare directly with them. See the overview's "Comparison runs (C1 to C3, D1 to D2)" section.
